## 演练 1｜跨境供应链需求优先级（正常路径）

| 字段 | 内容 |
|---|---|
| 编辑主题 | 跨境供应链需求优先级 |
| 场景入口 | **S-015**（需求太多，不知道砍什么） |
| 模型卡 | M-D03-01（减法与西瓜芝麻） |
| 行动工具 | **T-01** 取舍卡 |
| 路径 | 正常 |

### 背景

Q4 前只剩 6 周研发窗口。业务同时推：① 多仓库存共享规则、② 跨境退货逆向履约、③ 采购预测看板、④ 承运商 SLA 自动索赔。四条都标「P0」，排期表已满，履约客诉在涨。

### 走通步骤

1. **进场景**：对照 S-015 触发信号「排期永远满」→ 确认先用 M-D03-01，工具 **T-01**。
2. **T-01① 主矛盾**：主目标一句——「大促前把可售库存准确率拉到 99% 且跨仓调拨 T+1」。西瓜是①；②③④相对为芝麻或下期。
3. **T-01②③**：写约束——同一后端小组 ≤2 个并行需求；砍③采购看板（无稳定数据源）、④索赔（法务流程未闭环）。
4. **T-01④ 机会成本**：若硬做②退货，会挤掉①的联调窗口，大促超卖风险↑。
5. **T-01⑤ 反对席**：请仓储负责人列「不做①」的量化损失，避免只听销售口号。
6. **S-015 场景三步收口**：① 标西瓜/芝麻 ② 写「不做清单」 ③ 只留 Top3 → 本期实际 Top1：①；②降为预研；③④进 backlog 并写明解锁条件。

### 输出与复查

| 输出 | 决策：本期只做①；附机会成本一句 |
| 复查 | 4 周后看可售准确率与客诉是否被插单挤占（T-01 复查方式） |
| 走通结论 | **通过**——从 S-015 可在一次优先级会内完成 T-01 五步并落「不做清单」 |

## 演练 2｜库存与履约数据判断（异常路径）

| 字段 | 内容 |
|---|---|
| 编辑主题 | 库存与履约数据判断 |
| 场景入口 | **S-003**（我确信「亲眼所见」，却与数据矛盾） |
| 模型卡 | M-D01-01（审视感知与真知） |
| 行动工具 | **T-05** 信息甄别清单 |
| 路径 | **异常**（现场感知 vs 系统报表冲突） |

### 背景

巡仓时仓主管坚持「A 区爆款 SKU 还有 2000 件」，OMS 可售为 0，前台已下架。业务要你「先恢复售卖」。赌注高：错放会超卖，错信现场会持续缺货。

### 走通步骤（正常段）

1. **进场景**：S-003 → M-D01-01；对「厂商/仓内口头」类信源跑 **T-05**。
2. **S-003①**：请仓主管与系统管理员分别复述事实（批次、库位、占用单号），禁止混谈「应该有」。
3. **T-05**：要可复现——WMS 库存快照、冻结单、在途、渠道占用明细；标采用/暂缓/拒绝。

### 异常触发与处理

| 异常 | 只有仓内盘点草稿照片，无 WMS 导出；业务方催「先上架 500 测一下」 |
|---|---|
| T-05 演练口径 | 异常——只有 KPI/截图无完整案例 → **暂缓恢复售卖** |
| S-003③ | 在锚点未对齐前**下调置信度**，不拍板全量上架 |
| 追加动作 | 拉 WMS+OMS 对账任务；2 小时内出差异根因（常见：分仓策略变更未同步，呼应 **T-04** 演练类问题） |
| 工具退出 | 信息不足时不强行决策，符合 T-01/T-05 异常条款精神 |

### 输出与复查

| 输出 | 决议：维持下架直至对账完成；临时开通「仅 B2B 合同仓」可售若数据一致 |
| 复查 | 对账后更新 S-003 结论置信度；若属流程变更，走 **S-024**+**T-04** 沉淀检查项（关联演练，非本条主链） |
| 走通结论 | **通过（含异常）**——异常路径可走通：拒绝无锚点上架，并留下对账与降置信度记录 |

## 演练 3｜B 端系统方案评审（正常路径）

| 字段 | 内容 |
|---|---|
| 编辑主题 | B 端系统方案评审 |
| 场景入口 | **S-022**（项目要开工，但团队基础薄弱） |
| 模型卡 | M-D05-01（三条边与基线路径） |
| 行动工具 | **T-03** 方案评审三条边检查表 |
| 路径 | 正常 |

### 背景

集成商提交「跨境履约中台」方案：一期替换现有 OMS 履约模块，三期打通全球仓网。团队对旧 OMS 定制深、主数据质量差，但老板希望「一步到位」。

### 走通步骤

1. **进场景**：S-022 → ① 自检三条边 ② 补基线 ③ 画攀登路径；评审用 **T-03**。
2. **T-03① 下边·基线**：书面基线=当前 OMS 已上线能力（拆单、关单、部分跨境标签），**非**从空白画蓝图。
3. **T-03② 上边·极限**：全量替换一期不现实——缺统一 SKU 映射与历史订单清洗，触及「数据基线不足」异常类。
4. **T-03③ 第三条边·路径**：改为三期——P1 双写+对账；P2 切流 20% 站点；P3 关旧模块；每阶段有可验证里程碑。
5. **T-03④⑤**：点名缺数据工程师与对账规则负责人；要求举「上次大促对账失败」反例，避免只听 PPT。
6. **S-022 收口**：评审结论 **补基线/改路径**（非通过全量替换）。

### 输出与复查

| 输出 | T-03 输出：改路径；附缺失边=主数据与对账基线 |
| 复查 | P1 里程碑复盘时对照③是否仍成立 |
| 走通结论 | **通过**——与工具内 P6 草稿一致，且 S-022 三步与 T-03 五步无断点 |

## 演练 4｜跨部门协作（异常路径）

| 字段 | 内容 |
|---|---|
| 编辑主题 | 跨部门协作 |
| 场景入口 | **S-038**（跨部门项目扯皮、无人拍板） |
| 模型卡 | M-D07-03（分享利益与独立决策） |
| 行动工具 | **T-14** 跨部门对齐卡 |
| 路径 | **异常**（责任真空 + 资源被无限索取） |

### 背景

OMS 与 WMS 联调延期。物流要「系统马上支持新承运商」，研发说需求不清；双方在微信群互相 @，无单一决策人。供应链 PM 被两边拉去「免费支援」排障。

### 走通步骤（正常段）

1. **进场景**：S-038 → ① 写利益分配 ② 定独立决策人 ③ 留痕；执行 **T-14**。
2. **T-14**（对齐工具步骤）：写清各方赢/输什么；指定集成 **owner**（建议：履约产品+对方技术负责人双签）。

### 异常触发与处理

| 异常 | 物流坚持「先上线再补文档」；研发拒绝排期除非 PM 全职蹲点 |
|---|---|
| T-14 P6 演练口径 | ⑤ **拒绝无限免费支援**——PM 只承担接口定义与验收，不当双方外包 |
| S-038② | 升维：请供应链总监指定**独立决策人**（单点拍板联调范围与日期） |
| S-038③ | 会议纪要只留：范围、日期、责任人、阻塞项；情绪性长文转 **S-032** 高带宽沟通 |
| 利益交换 | 物流获得「承运商模板」排期；研发获得「冻结需求两周」；PM 输出接口说明书而非 7×24 排障 |

### 输出与复查

| 输出 | 书面决议：owner、里程碑、PM 边界；拒绝「先上后补」 |
| 复查 | 联调周会核对 T-14 输出是否被遵守 |
| 走通结论 | **通过（含异常）**——异常下仍可走通：拍板人+边界+拒绝无限支援 |

## 演练 5｜专业成长与职业迁移（正常路径，含工具内异常分支）

| 字段 | 内容 |
|---|---|
| 编辑主题 | 专业成长与职业迁移 |
| 场景入口 | **S-035**（供应链 PM 要证明 B 端系统价值却难量化）+ **S-029**（30+ 焦虑裁员） |
| 模型卡 | M-D06-01（职场价值可见）；M-D06-03（赛道与可迁移性） |
| 行动工具 | **T-10** 职业选择与迁移盘点；**T-08** 伪工作自检 |
| 路径 | 正常主链 + **T-10 规定异常分支** |

### 背景

你在传统 ERP 实施型 PM 岗位多年，公司押注跨境独立站履约。述职在即：业务觉得「系统只是成本中心」；你担心技能老化，想转「跨境履约平台 PM」但时间碎片化。

### 走通步骤

1. **价值可见（S-035）**：**T-08** 列近 4 周可验证成果（如：关单时效、库存差异率、一次对账挽回金额）→ 对齐业务 KPI 故事，非功能清单。
2. **S-035 三步**：① 指标对齐业务结果 ② 里程碑同步干系人 ③ 复盘可引用案例。
3. **迁移盘点（S-029）**：跑 **T-10**——① 突出可迁移能力：系统集成、主数据、跨仓履约规则、B 端干系人管理。
4. **T-10 异常分支（走通）**：判断「行业仍增长但岗位技能老化」→ 走步骤②③ **升级而非裸辞转行**——6 个月计划：1 个对外可见案例（如演练 3 的中台路径裁剪）+ 1 项认证/内部分享。
5. **S-029 收口**：盘点现金流与学习计划（不给出买卖建议）；与 **T-13** 个人结余目标可并行但本条不展开。

### 输出与复查

| 输出 | 述职一页纸：3 个业务指标+案例；T-10 书面：升级路径与 6 个月里程碑 |
| 复查 | 季度看外部可见作品是否产出；T-08 防「清单爆炸」 |
| 走通结论 | **通过**——S-035/S-029 与 T-08/T-10 可串联；异常分支按工具字段执行 |

## AC-6.6 自检

| # | 标题 | S- | T- | 异常 |
|---|---|---|---|---|
| 1 | 跨境供应链需求优先级 | S-015 | T-01 | — |
| 2 | 库存与履约数据判断 | S-003 | T-05 | 是 |
| 3 | B 端系统方案评审 | S-022 | T-03 | — |
| 4 | 跨部门协作 | S-038 | T-14 | 是 |
| 5 | 专业成长与职业迁移 | S-035、S-029 | T-08、T-10 | 工具异常分支 |
| 合计 | 5 条 | 7 个场景 ID 引用 | 6 个工具引用 | ≥2 条显式异常路径 |

**本质**：手册价值不在「读过模型卡」，而在**高赌注工作情境**里能用 S 入口定位问题、用 T 步骤产出可复查的书面决策；异常路径验证的是「数据不足/扯皮/感知冲突」时是否停线而非硬答。

**对 PM 的启发**：把 OMS/WMS 争议都当成「信源与决策留痕」问题——先 SSOT 与责任人，再排期；优先级与方案评审共用「基线+路径」语言，可减少跨部门返工。
