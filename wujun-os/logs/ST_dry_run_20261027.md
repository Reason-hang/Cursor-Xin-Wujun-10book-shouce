## ST-5：文件损坏恢复

### 规程

人为损坏 `state/state.json`（或未来 P1+ 的某张卡文件），须满足：

1. **能发现**：机读状态无法渲染或 `verify_pack` 报哈希不一致；
2. **能重建**：从 `state/journal.md`、`state/STATE.md`（上次渲染快照）、恢复包 zip、或 Git 历史恢复 `state.json`；
3. **能告警**：修复后跑 `make verify-pack` / `make gates` 确认清单一致。

### 可执行命令（请在仓库根执行，先备份）

```bash
cd "/Users/lizhihang/Documents/【Cursor-projects】/Cursor-Xin-Wujun-10book-shouce/wujun-os"
cp state/state.json state/state.json.bak
echo '{bad json' > state/state.json
python3 scripts/status.py
```

预期：`json.decoder.JSONDecodeError`（无法渲染 STATE）。

**恢复路径（任选其一）**

```bash
# 路径 1：本地备份
cp state/state.json.bak state/state.json
python3 scripts/status.py

# 路径 2：从最新恢复包解压覆盖 state/
unzip -p dist/wujun-os-pack_20261027.zip wujun-os/state/state.json > state/state.json
python3 scripts/status.py

# 路径 3：Git（若已提交）
# git checkout -- state/state.json
```

恢复后校验：

```bash
make verify-pack
make status
```

2026-10-27 实测：损坏后 `status.py` 失败；从 `.bak` 恢复后 `status` 正常。

**ST-5 判定：通过（发现 + 重建路径明确）。** P1 起增加「损坏单卡 + 台账/journal 重建」复测。
